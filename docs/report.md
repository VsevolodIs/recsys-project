# Рекомендательная система для e-commerce (Amazon Music)

## 1. Бизнес-контекст и цель проекта

Главная цель рекомендательной системы — показывать пользователю товары, которые могут ему понравиться. Это должно помочь увеличить количество покупок, заинтересованность пользователей и среднюю сумму заказа.

Для проекта используется датасет Amazon Music Reviews. В нём есть информация о пользователях, товарах и оценках. Основные поля:

* `reviewerID` — пользователь;
* `asin` — товар;
* `overall` — оценка товара;
* `unixReviewTime` — время, когда был оставлен отзыв.

На основе этих данных можно посмотреть, какие товары нравятся разным пользователям, и попробовать предсказывать, что может понравиться конкретному человеку.

## 2. Основные проблемы

## Холодный старт

Одна из главных проблем рекомендательных систем — холодный старт. Он появляется, когда у нас недостаточно информации о пользователе или товаре.

### Новый пользователь

Если человек только зарегистрировался и ещё ничего не смотрел и не покупал, система пока не понимает, что ему интересно.

Можно предложить ему небольшой опрос: например, спросить, какие инструменты или категории товаров ему интересны. Ещё проще — сначала показывать популярные товары.

Но у опроса есть минус: не каждый пользователь захочет его проходить. Чем больше действий нужно сделать после регистрации, тем выше вероятность, что человек просто уйдёт.

Поэтому можно использовать сессионные рекомендации. В таком случае пользователю не нужно заранее рассказывать о своих интересах. Система сама смотрит, какие товары он открывает, и уже после нескольких действий начинает менять рекомендации.

Например, если пользователь посмотрел несколько гитар и аксессуаров для них, система может начать показывать ему похожие товары.

### Новый товар

Похожая проблема возникает, когда в магазине появляется новый товар. У него ещё нет отзывов и покупок, поэтому система не может понять, кому его рекомендовать.

В таком случае можно использовать информацию самого товара: название, описание, бренд и категорию. То есть даже без отзывов можно примерно определить, каким пользователям товар может подойти.

Также можно специально иногда показывать новые товары пользователям, чтобы собрать первые оценки и понять, насколько они интересны.

## Нежелательные рекомендации

Ещё одна проблема — рекомендации типа «С этим товаром покупают».

Если строить их только на основе статистики, иногда могут появляться странные рекомендации. То, что два товара часто покупали одни и те же люди, ещё не означает, что их обязательно нужно предлагать вместе.

Поэтому кроме самой статистики стоит учитывать категории товаров и их характеристики.

Например, для некоторых товаров можно заранее определить сочетания, которые не стоит рекомендовать. Это можно сделать с помощью простых правил.

Но здесь тоже есть проблема: если сделать слишком много таких правил, система станет слишком ограниченной и может перестать показывать хорошие рекомендации.

Поэтому лучше использовать небольшое количество основных ограничений и дополнительно проверять рекомендации перед тем, как показать их пользователю.

# Итог

При создании рекомендательной системы важно учитывать не только сам алгоритм, но и реальные проблемы, которые могут возникнуть при его использовании.

В первую очередь нужно решить проблему новых пользователей и товаров, для которых ещё нет истории. Для этого можно использовать популярные товары, действия пользователя во время сессии и информацию о самом товаре.

Также нужно следить за тем, чтобы рекомендации были нормальными и подходили друг другу. Для этого можно использовать категории товаров и простые ограничения.

Таким образом, рекомендательная система должна не просто находить похожие товары, а учитывать контекст и постепенно учиться на действиях пользователей.
